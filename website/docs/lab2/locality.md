# 矩阵转置与局部性

## 1. 二维下标怎样变成地址？

对于行优先的 N×N 矩阵，第 i 行、第 j 列的元素位于一维数组下标：

```text
index(i,j) = i × N + j
```

相邻列的下标相差 1，相邻行同一列的下标相差 N。实验元素为 `uint32_t`，一个元素占 4 字节。

## 2. 普通转置在读写什么？

简化实现如下：

```cpp
for (size_t i = 0; i < N; ++i) {
    for (size_t j = 0; j < N; ++j) {
        B[j * N + i] = A[i * N + j];
    }
}
```

固定 i、增加 j 时，A 的读下标每次加 1，B 的写下标每次加 N。下一次写入 B 的相邻列，需要等到外层 i 增加之后。

## 3. 缓存行与局部性

CPU 通常以**缓存行**为单位与内存交换数据。一次访问可能带入附近的一组字节。如果后续很快用到附近的数据，这次传输就能被充分利用，这称为空间局部性。

如果同一数据或所在缓存行很快再次被使用，就有时间局部性。这里的“很快”取决于中间又访问了多少其他数据：缓存容量有限，旧数据可能在再次使用前被替换。

普通转置中，B 的写入跨越多行，可能同时涉及较多缓存行。等到写相邻列时，先前的缓存行是否仍在缓存里，就成为需要关注的问题。

!!! note "知道访问方式，不等于已经测到了缓存未命中"
    本实验输出元素数、有效带宽和时间，没有直接统计 CPU 的缓存未命中次数。可以结合布局解释现象，但不要把这些字段当作硬件性能计数器。

## 4. 二维分块怎样改变顺序？

把矩阵划分为 `tile × tile` 的区域，先处理完当前块，再进入下一块。

```cpp
for (size_t ii = 0; ii < N; ii += tile) {
    for (size_t jj = 0; jj < N; jj += tile) {
        for (size_t i = ii; i < std::min(ii + tile, N); ++i) {
            for (size_t j = jj; j < std::min(jj + tile, N); ++j) {
                B[j * N + i] = A[i * N + j];
            }
        }
    }
}
```

最内层仍是连续读 A、跨行写 B，但跨越的 B 行限制在当前 tile 内。处理相邻 i 时，会较快回到这些行的相邻元素，缩短再次访问同一缓存行的间隔。

分块没有改变最终的元素对应关系，也没有减少要写入的元素数，改变的是访问顺序和活跃数据范围。

## 5. 分块怎样交给线程？

实际实现把 ii、jj 两层块循环交给 OpenMP，使用 `collapse(2)` 将两层迭代组成任务空间，并静态分配。

每个输入块对应一个独立的输出块，不同任务不会写同一个元素。尾部块通过截断范围处理不满一个 tile 的区域。

阅读代码时，按下面的顺序：

1. `src/transpose_serial.cpp`：确认普通转置的读写下标。
2. `src/transpose_parallel.cpp`：找到按行并行的任务单位。
3. `src/transpose_tiled.cpp`：找到二维块循环、边界截断和线程统计。

## 6. 动手试一试

按[操作步骤](run.md)构建后先执行快速验证，再运行完整测量。固定一个 N 和线程数，比较 Naive 与不同 tile 的时间；再固定 tile，看它在不同 N 下的表现。

```bash
python3 run.py --n 4096 --tile 16 32 64 128 --output results/n4096
```

```bash
python3 run.py --n 2048 3072 4096 6144 8192 --tile 64 --output results/tile64
```

观察时可以依次确认：

1. 各实现的 `updates` 是否对应同样的矩阵元素数？
2. 在同样线程数下，改变 tile 后时间怎样变化？
3. 固定 tile、增加线程时，`thread_speedup` 怎样变化？
4. 如果更多线程没有继续改善时间，哪些资源可能已成为限制？

`effective_gbps` 按“一次逻辑读 A + 一次逻辑写 B”计算。实际总线流量还受缓存、写分配等机制影响，因此它是便于比较的有效带宽。

??? info "这与 Lab1 的负载均衡有什么区别？"
    这里每个元素只需复制一次，完整行包含相同数量的元素。分块的主要出发点是数据访问顺序。线程时间差异仍可能出现，但不能因为存在等待就把局部性实验全部解释为负载不均衡。
